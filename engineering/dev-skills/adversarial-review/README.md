# adversarial-review

A structured contradiction of finished work and the decisions behind it. A
challenger assumes the result is wrong and attacks it with concrete scenarios;
the author holds it only by answering with ranked evidence. A referee stop rule
forbids both rubber stamping and endless obstruction.

- Inputs: a claim, a decision, a verdict or a result, and the work behind it.
- Outputs: challenges, rebuttal record, standing verdict.
- Depends on: engineering-core.
- Lateral: code-review-protocol, self-critique-protocol, testing-quality.
- Downstream: validation-gate, project-continuity, git-workflow.

Authority is not evidence. A challenge dies only on a run, a cited source, a
reproducible scenario or a conceded counterexample, and a side that only
repeats itself has lost that point.
