# Capture checklist

Run before the first take of a session, and the frame review after every kept
take.

## Before recording

- [ ] The build, environment and accounts are the ones in the rights record.
- [ ] Demo data seeded by script; names and emails on reserved example domains.
- [ ] Fresh browser profile: no other tab, no bookmarks bar, no extension, no
      saved login, no autofill.
- [ ] System notifications silenced; desktop, dock and personal menu items
      hidden; clock hidden or neutral.
- [ ] Secrets read from the environment; none typed, none in a URL.
- [ ] Viewport and device scale set for the format (16:9 or 9:16), higher scale
      where a zoom above 1.5x is planned.
- [ ] Terminal and editor: high-contrast theme, font legible at the smallest
      target screen, neutral prompt.
- [ ] Cursor visible, smooth movement, click feedback on.

## Per take

- [ ] Take identifier, beat, date and time logged.
- [ ] Project commit or version and capture script commit logged.
- [ ] The result on screen came from the running project.
- [ ] Zoom ranges and rectangles written to the zoom map.

## Frame review, at capture resolution

- [ ] No token, key or password visible, including in a header panel or
      history.
- [ ] No name or email that is not demo data.
- [ ] No internal URL, host name or file path that reveals anything.
- [ ] No notification, other application or personal file name.
- [ ] Kept, or discarded and re-captured. A blur only with the owner's
      agreement, recorded in the log.
