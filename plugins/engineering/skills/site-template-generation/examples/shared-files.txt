# The code the two site examples share, held once in _shared/.
#
# The portfolio-sports-coach and showcase-electrician examples share the same
# site shell, back office, route handlers, request proxy, Next configuration,
# service worker and operator scripts; they differ only in their content model
# (lib/types, lib/schema, lib/legal, lib/content, lib/instance), their public
# pages, their data and their trade tokens. The files below live in _shared/
# and nowhere else. Each example installs _shared as the local package
# site-template-shared and imports these modules from it; the shared code
# receives the per-app content model as props and arguments (the instance of
# lib/instance.ts), and never imports it. See _shared/README.md.
#
# What Next requires inside each app stays there as a thin file that delegates
# here: the route files under app/, proxy.ts and next.config.mjs. Those, and
# every other file still identical in both examples, are listed with their
# reason in app-local-files.txt.
#
# A CI guard holds the arrangement: every path below exists in _shared/, none
# exists in either example (a copy would shadow the source and drift), every
# file in _shared/ other than README.md and package.json is listed here, the
# shared code imports nothing from an example, both examples are wired to the
# package, no file is identical in both examples unless app-local-files.txt
# lists it, and no example keeps a middleware.ts.
# One path per line, relative to _shared/.
